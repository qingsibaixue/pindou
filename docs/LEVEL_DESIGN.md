# 拼豆关卡设计原则

## 核心体验

玩家享受的是一整片豆豆同时抬起、移动、倾倒和锁定的反馈。关卡的基本单位是“豆群”，不是单颗豆。

每关遵循同一个节奏：

1. 开局棋盘铺满，托盘为空。
2. 玩家拿起一整片错位豆群，放入托盘腾出空间。
3. 其他大豆群按颜色循环依次回到正确底色。
4. 最后把托盘中的整组豆豆倒回棋盘，完成图案。

## 硬性验收标准

- `trayBeans` 必须为空。
- 棋盘开局不能有 `beanColorId = -1` 的空洞。
- 每个可移动连通组至少 12 颗豆。
- 豆群允许超过20格托盘；超出的部分必须形成有意设计的第二轮换位，不能只是无意义拆碎。
- 超容量豆群按画布设计控制在21–40颗；20格托盘会让它们产生一至两轮有意义的分批。
- 所有颜色数量守恒。
- 初始错位必须由完整色块的循环换位产生，不能随机交换单格。
- 每关至少有 3 个可移动大豆群。

## 难度曲线

- 1–3 关：爱心、花朵、小鱼，3 个大豆群，每组 16–17 颗，建立中转概念。
- 4–9 关：星星、火箭、猫咪、蛋糕、蝴蝶、皇冠，4 个大豆群，每组 14–18 颗，增加区域辨识与移动顺序。
- 第10关：24颗四色回廊，首次超过20格托盘，教学“先完成大块、再收尾余量”的两段式解法。
- 11 关：糖果列车改为竖屏 S 形车轨，四节车厢纵向推进，避免宽画布把豆豆压小。
- 12–15 关：鲸鱼、帆船、城市、乐章使用各自的场景构图；4 个 24 颗豆群保留需要规划空间的节奏，但不向玩家解释内部拆分机制。
- 16–20 关：纵向叙事。大树生长、灯塔守望、气球上升、火箭升空、瀑布下坠都使用 20–25 行的高画布；4 个 24 颗豆群必须分两轮搬运。
- 21–30 关：五色场景章，风筝、鱼群、飞行编队、山谷、轨道、阶梯、橱窗、接力、长街、祥云；5 个 30 颗豆群，交替使用一步和两步五色循环。
- 31–40 关：大型建筑章，雪山、潜艇、城堡、木屋、龙门、月球基地、工坊、冰宫、鲸岛、沙漏；5 个 36 颗豆群，每轮形成 20+16 的连通分批。
- 41–50 关：六色终章，舰队、双龙、花园、都市、学院、银河列车、乐园、神殿、世界拼图、万象庆典；交替使用完整六色循环、两组三色循环和三组双色循环。

难度只通过豆群数量、区域形状和循环关系增长，不通过制造零碎错误增长。

## 创意验收

每关设计前先回答三个问题：玩家第一眼认出什么、画布比例为什么只能这样、移动大豆群时发生了什么“小故事”。答不出来就不进入数据制作。

- 宽画布表达行进、航行、延展和节奏。
- 高画布表达生长、守望、升空和坠落。
- 正方画布只留给中心构图、旋转和对称关系。
- 图案轮廓、颜色分区与操作顺序必须互相解释，不能只在名字上包装随机区域。
- 同一章不连续复用相同轮廓、相同比例和相同解法。

棋盘支持 2–32 行、2–32 列，并在 600×600 的显示区内自动缩放豆子。改变棋盘尺寸是创作工具，不是关卡差异本身。

## 自动检查

运行：

```bash
node tools/generate-levels.mjs
```

生成器会拒绝托盘预置豆、棋盘空洞、小于12颗的初始碎片组以及颜色数量不守恒的关卡。超过托盘容量会标记为“需分批”，作为策略机制保留。

全面检查：

```bash
node tools/test-levels.mjs
```

测试覆盖 50 关的唯一名称、唯一轮廓、独立提示、颜色守恒、豆群连通、20+余量双侧连通、循环结构和 600×600 显示边界。
