# 多平台小游戏发布清单

## Cocos 构建目标

本工程锁定 Cocos Creator 3.8.0。该版本内置 `wechatgame` 和 `bytedance-mini-game` 构建目标；当前安装版本未内置快手构建目标，因此快手不能把微信包直接当正式包提交，需要接入快手官方/渠道提供的 Cocos 适配插件或转换工具，并在目标开发者工具中复测。

建议分别建立三套构建配置，输出到不同目录，避免相互覆盖：

- 微信小游戏：`build/wechatgame`
- 抖音小游戏：`build/bytedance-mini-game`
- 快手小游戏：`build/kuaishou-mini-game`（由所采用的快手适配链生成）

## 每个平台必须填写

1. 平台 AppID、游戏名称、版本号和隐私说明。
2. 启动场景选择 `Game.scene`，方向选择竖屏。
3. 图标优先使用 `assets/art/icon/game-icon-1024.png`，平台要求小图时使用同目录的 512/256/128 版本。
4. 首包体积超限时，把后续关卡和音频拆成远程资源包；首包至少保留第一关、基础 UI、所有核心脚本。
5. 打开代码分包/资源分包后，在真机低端设备检查首屏时间和切后台恢复。

## 上线前验收

- 冷启动出现主页；开始、暂停、继续、重开、返回主页均可闭环。
- 切后台再回来时停在暂停页，不发生误触或计时继续。
- 50 关都可加载，通关后只解锁下一关，重新启动后进度仍保留。
- 无网络时第一关能进入；分享/震动 API 不可用时不影响游戏。
- 360×640、390×844、430×932 三档竖屏无遮挡，刘海和圆角屏按钮可点击。
- Android 与 iOS 真机都检查触控、字体、透明 PNG、音量和性能。
- 微信、抖音、快手分别使用各自开发者工具和至少一台真机验收，不能只用 Web 预览代替。

## 仍需平台账号侧完成

仓库不能代替平台后台配置。正式上架前还需要开发者账号、AppID、主体认证、隐私政策地址、类目/版号材料（如适用）、广告位与分享文案。上述信息确定后再写入各平台构建配置，避免把测试 AppID 提交到正式包。
